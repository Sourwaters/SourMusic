SourMusic v10 — общая музыка через Firebase

ТВОЙ OBS
1. Источник музыки: https://sourwaters.github.io/sourmusic-embed-test/?role=source&v=10
2. Док: https://sourwaters.github.io/sourmusic-embed-test/?role=control&v=10
3. В доке скопируй «Код для Streamer.bot», замени код существующего действия SourMusic State, нажми Compile и Save. Не создавай второе одноимённое действие.
4. В доке включи «Подключить очередь второго стримера». Отправитель заказов: xwaran.
5. Скопируй появившуюся ссылку для второго стримера и передай xwaran лично.
6. Оставь один основной источник музыки. Не включай «Отключать источник, когда не виден» и автоматическое обновление при активации сцены.

OBS XWARAN
Добавить источник «Браузер» с полученной ссылкой. Док, Streamer.bot для воспроизведения и вход в Firebase не нужны.
В обоих OBS включить «Управлять аудио через OBS» в свойствах музыкального источника. В расширенных свойствах аудио выбрать «Мониторинг и вывод», если музыку должны слышать и зрители, и стример. Не дублировать этот же звук захватом рабочего стола.

ЗАКАЗЫ С КАНАЛА XWARAN
1. Во время совместного эфира включить общий чат Twitch между каналами.
2. В её Streamer.bot подключить broadcaster-аккаунт xwaran.
3. Создать действие для её музыкальной награды: Twitch → Channel Reward → Reward Redemption. Награда должна требовать ввод ссылки YouTube.
4. В действие добавить Execute C# Code, вставить SourMusic-SendRequest.cs, Compile, Save.
5. Код отправляет от xwaran сообщение в чат: !addsourmusic URL ник_заказчика redemption_id.
6. Твой Streamer.bot должен получать это сообщение в общем чате. Источник принимает команду только от логина, указанного в доке. Повтор того же redemption_id не добавляется.
Твоя награда остаётся «Заказ музыки SourMusic».

УПРАВЛЕНИЕ
Твой источник ведёт общую очередь; пауза, продолжение и следующий трек из твоего дока передаются второму плееру через Firebase. Обновления позиции — каждые 5 секунд и при изменениях. Это синхронизация воспроизведения, не гарантия одинакового звука до миллисекунды: задержки YouTube и буферизация различаются.
Если основной источник отключён, второй плеер приостанавливается (при потере связи — не позднее проверки устаревшего состояния через 30 секунд).
По умолчанию общая очередь выключена. При выключении обычный плеер продолжает работать локально.

ССЫЛКИ И ХРАНЕНИЕ
GitHub хранит страницы плеера. Firebase хранит состояние трека, позицию и очередь, но не аудио.
Ссылка второго плеера даёт чтение комнаты; не публикуй её в общем чате. Запись разрешена только идентификатору основного плеера.
Не очищай данные браузерного источника без необходимости. При потере его идентификатора создаётся новая комната — скопируй новую ссылку второму стримеру.
Очередь в основном плеере пока не восстанавливается после перезагрузки: не обновляй источник посреди очереди.
Для первоначального теста: заказать по треку на каждом канале, нажать паузу/продолжить/следующий в твоём доке и проверить второй OBS.
